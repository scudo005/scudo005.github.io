--- layout: post title: Ryujinx can't (couldn't?) be compiled --- After Nintendo successfully managed to close down the Ryujinx project, out of curiosity I tried to compile its source code, as the repo had been backed up and reuploaded both on GitHub and the Internet Archive.
There still were (and are) builds for Windows and Linux, and my notes from back then say the Flatpak version was still available on Flathub.

Also, back then I was experimenting with C#/.NET and Ryujinx is written in C#, so I figured I could give it a try.

What I found is that the project did not build, and for quite complicated reasons.

Analyzing the build logs, I found there were a lot of errors saying things like:

error CS0535: 'UnregistrationNotifier' does not implement interface method 'IServiceObject.GetCommandHandlers()'

Generally speaking, all of these errors referred to classes and project related to managing HorizonOS system calls.

I took a look into it; I loaded the repo into VSCodium and I let it crunch through all the files until it started giving out errors; I then grabbed a random class that errored out, that referenced an interface.

I was then welcomed with the sight of a completely empty interface:

interface IReceiverService : IServiceObject
    {
    }

Great. An empty interface that extends another interface. What an amazing start.

But what does IServiceObject contain? Not much, actually:

interface IServiceObject
    {
        IReadOnlyDictionary GetCommandHandlers();
    }

Great. Another (almost) empty interface.

dopo il casino con Ryujinx, mi sono messo a cercare di compilare il codice sorgente; build per Windows e Linux di tutti i tipi sono presenti ovunque (pure la versione Flatpak sta ancora sulle repo), per cui era più per curiosità. come sapete se avete letto il gruppo, Ryujinx non builda, ma il motivo per cui non lo fa è abbastanza assurdo. sono partito dall'analizzare i log: tutti gli errori erano qualcosa del tipo "error CS0535: 'UnregistrationNotifier' non implementa il membro di interfaccia 'IServiceObject.GetCommandHandlers()". tutti gli errori si riferivano a classi e progetti che servono a gestire le system calls fatte ad HorizonOS, l'OS della Switch. ora, cos'è quel metodo? così ho pigliato la repo e ho dato il tempo a VSCodium di elaborare tutti i file, finché non sono iniziati ad apparire errori, poi ho preso una classe a caso che dava errori, che mi ha rimandato a una interfaccia, per poi ritrovarmi la gioia di una interfaccia vuota davanti agli occhi: interface IReceiverService : IServiceObject { } benone. una interfaccia vuota che estende un'altra interfaccia. iniziamo bene. ma cosa c'è in IServiceObject? non molto: interface IServiceObject { IReadOnlyDictionary GetCommandHandlers(); } benone, un'altra interfaccia semivuota. vabbè, una collezione. (IReadOnlyDictionary è un oggetto di System.Collections.Generic.) ma quel GetCommandHandlers() è esattamente il metodo che faceva fallire la compilazione! così, vado a cercare tutti i riferimenti a quel metodo, che viene chiamato solo una volta nell'intero progetto, all'interno di ServiceDispatchTables, una classe che dovrebbe gestire i command handler relativi alle syscall di HorizonOS: public static ServiceDispatchTableBase Create(IServiceObject instance) { if (instance is DomainServiceObject) { return new DomainServiceObjectDispatchTable(); } return new ServiceDispatchTable(instance.GetType().Name, instance.GetCommandHandlers()); } bene, arriviamo su un costruttore persino, e abbiamo la nostra call a GetCommandHandlers, un metodo invocato sull'oggetto instance, che è... (rullo di tamburi) una istanza di IServiceObject! yay! abbiamo chiuso il cerchio apparentemente, no? no, perché IServiceObject è una interfaccia, e le interfacce per definizione non sono istanziabili in un oggetto (oltretutto IServiceObject non ha un costruttore, per cui non è possibile istanziarne un oggetto in ogni caso). ottimo, grazie dev team di Ryujinx. ma concentriamoci piuttosto su quella call a GetCommandHandlers. siccome la call è invocata su un oggetto di tipo IServiceObject, bisogna vedere all'interno di IServiceObject se esistono metodi chiamati GetCommandHandlers(), e difatti c'è menzione di un metodo con quel nome, che è l'unica cosa presente all'interno di quella interfaccia. ma cosa fa quel metodo? GetCommandHandlers dovrebbe restituire una collezione di tipo IReadOnlyDictionary, ovverosia una coppia di valori key-value read-only dove la chiave è un numero intero e il valore è un oggetto di tipo CommandHandler, che idealmente è quello che vogliamo avere. il problema è che questa definizione di GetCommandHandlers è definita all'interno di una interfaccia, per cui sta alle singole classi che implementano l'interfaccia IServiceObject, ovverosia tutte le classi che gestiscono le funzionalità emulate di HorizonOS, implementare GetCommandHandlers. (tecnicamente dichiara la firma del metodo e non la sua funzionalità, che puoi fare nelle interfacce) il problema è che nessuna classe in tutto il progetto implementa GetCommandHandlers. ahia. in pratica si sono dimenticati di implementare una cosa che usano letteralmente TUTTE le classi che implementano le syscalls di HorizonOS in software. davvero un ottimo lavoro.
